# Checklist — Startup PM

> Reusable checks for the Startup PM reviewer — the product/founder lens.
> Source of truth: `CLAUDE.md §1` (IS/NOT), `docs/goals.md`, `user-preferences` memory, Ponytail principle.
> Severity rubric in `docs/REVIEW_PROCESS.md`. Mark each finding **Blocker / Major / Minor**.

## Product identity (does this serve what BeActive IS?)
- [ ] Advances the **daily social habit engine / behavioral accountability** thesis.
- [ ] Does **not** drift toward what BeActive is NOT: fitness tracker, generic social feed, Strava clone.
- [ ] Reinforces the core loop: proof → verify → streak → social accountability → retention.

## Scope discipline (Ponytail at the product level)
- [ ] This is the MVP-minimal version of the value — no speculative features bolted on.
- [ ] No new infrastructure without proven need (CLAUDE.md principle 5).
- [ ] Fits a known slice in `goals.md`; if it invents new scope, that is called out explicitly.
- [ ] Shortest path to user value chosen over the "complete platform" version.

## Activation / retention impact
- [ ] Change has a plausible positive effect on activation, D1/D7 retention, or streak survival.
- [ ] Does not add friction to the critical path (upload → verify → streak in <30s).
- [ ] Emotional payoff / delight present where the moment warrants it (streak win, first post).

## Founder economics
- [ ] No cost spike (AI calls, storage, serverless time) disproportionate to the value added.
- [ ] Time-to-ship is proportionate; not gold-plating a pre-seed MVP.
- [ ] If it's a polish task, it targets a benchmark surface (the screens users judge on).

## Risk to the narrative
- [ ] Nothing here would embarrass a "funded by a top SV startup in 2026" demo.
- [ ] No half-built feature shipped to the critical path (better cut than half-done).
